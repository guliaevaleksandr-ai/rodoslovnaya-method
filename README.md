# Поиск родни: методика и инструменты

Рабочая система, по которой мы ищем предков по архивам бывшего СССР и Российской империи вместе с ИИ-помощником.
Здесь только **методика, шаблоны и инструменты** — семейных данных в репозитории нет.
Все люди в примерах (Соколовы, Ветровы, Лебедевы, Морозовы, город Энск, село Заречье, архив «ГАЭО») — **выдуманы**.

```
README.md                  — этот файл: как устроен поиск
fan/                       — «Веер предков»: сборщик интерактивной страницы
  fan_build.py             — собирает один HTML из JSON + картинок
  fan_template.html        — шаблон страницы (SVG-веер, карточки, хроника)
  demo/family.json         — выдуманная семья для примера
templates/                 — пустые реестры дела (с 1–3 демо-строками)
  research-state.md        — очередь, блокировки, «последняя точка»
  search-log.csv           — журнал поиска: каждый запрос, даже пустой
  person-register.csv      — люди и кандидаты
  artifact-register.csv    — находки с архивными шифрами
  claims-register.csv      — утверждения и на чём они держатся
  relationship-register.csv— связи между людьми
tools/yandex_archive.js    — хелперы для Яндекс «Поиска по архивам» (вставляются в консоль браузера)
```

## 1. Главные правила

- **От известного к неизвестному.** Один шаг — одна связь (ребёнок → родители). Через поколение не прыгаем.
- **Находка ≠ факт.** Любая находка сначала идёт в `artifact-register.csv` с шифром (архив, фонд, опись, дело, лист/скан), потом — вывод в `claims-register.csv`.
- **Однофамильцев не сливаем**, пока нет совпадения минимум по двум независимым признакам (год + место, родители, адрес, приход).
- **Читаем скан, а не сниппет.** OCR путает «рождение» и «смерть»: запись «солдата N сын Алексий» оказалась записью о смерти младенца.
- **Юрисдикция — на дату события.** Сёла переходили из губернии в губернию, из края в область; две семейные версии «родом из губернии А» и «из области Б» могут обе быть верны для разных лет.
- **Имена менялись.** Светские и церковные формы (Иоанн ↔ Иван, Евфимий ↔ Ефим), новые советские имена, ошибки писарей, фамилия из отчества. Ищем все варианты.
- **Семейная память — источник, а не истина.** «Танкист, пропал без вести» по документам может оказаться «миномётчик, убит, медаль». Храним обе версии и помечаем, чья.

### Метки достоверности

В рабочих заметках каждая строка о человеке помечается, откуда мы это знаем:

| Метка | Что значит | Пример |
|---|---|---|
| 📄 | **документ**: есть шифр, скан открыт глазами | метрика 1901, ф. 000, оп. 2, д. 345, № 17 |
| 🔎 | **находка поиска**: сниппет, OCR, строка описи, карточка без скана — направление, ещё не факт | в выдаче Яндекс Архива мелькнул «Ильи Петрова сын» |
| 👪 | **со слов**: родственники, генеалоги в чатах — пишем, чья версия | «по словам тёти — погиб в 1941» |

Комбинация «📄+🔎» в выводе = документ подтверждён ещё и поисковой находкой из другого источника.
Статусы в реестрах: `document` · `confirmed` (≥2 независимые цепочки) · `family` · `hypothesis` · `namesake-candidate` · `rejected`.

### Журнал поиска

`search-log.csv` — **каждый** запрос, включая пустые и упёршиеся в капчу. Зачем:
- пустой результат тоже знание («в ОБД нет» ≠ «не воевал»: выжившие в ОБД не попадают);
- не повторяем одно и то же в следующий заход;
- ИИ-помощник в новом окне продолжает с того же места.

`result_status`: `found` · `no-match` · `too-many` · `blocked-captcha` · `blocked-login` · `site-down`.

## 2. Где ищем — по слоям времени

1. **1990–2020-е.** Документы на руках у семьи (трудовые книжки, свидетельства о браке, профбилеты, удостоверения к медалям), кладбищенские базы, некрологи.
2. **1941–1945.** «Память народа» (pamyat-naroda.ru), ОБД «Мемориал» (obd-memorial.ru), «Подвиг народа»; книги учёта призванных по военкоматам — в областных архивах (часто есть в Яндекс Архиве); ЦАМО — письмом или через Госуслуги.
3. **1918–1930.** Книги ЗАГС волостей, посемейные списки 1920 г., похозяйственные книги (районные архивы), списки лишенцев.
4. **До 1917.** Метрические книги (фонд духовной консистории), исповедные ведомости, ревизские сказки; для казаков — списки малолеток и станичные документы.
5. **Старообрядцы.** Если в православных метриках семьи нет — единоверческая церковь и «книги о раскольниках» (после 1874 г. — в волостных правлениях).

### Яндекс «Поиск по архивам» — yandex.ru/archive
Главный онлайн-источник по метрикам и ЗАГС.
- Документы видны **только после входа** в аккаунт Яндекса.
- `https://yandex.ru/archive/search?text=<запрос>&dateFrom=<ГГГГ>&dateTo=<ГГГГ>` — даты только годами.
- Учитываются словоформы, дореформенная и современная орфография.
- Расшифровка скана: `.../archive/catalog/<uuid>/<скан>?tab=structured` — там видно, родившийся это или умерший.
- Что срабатывает: **место вместо фамилии** («Соколов Энск», «хутора Ольхового»), церковная форма имени, редкое имя + ошибка писаря, сословие («малолеток», «казак»), название учреждения («Заречном ВИК») — находит строки описи даже неоцифрованных книг.
- Проверить, какие годы книги вообще оцифрованы: запрос по названию села с `dateFrom=dateTo=год`.
- База пополняется — повторяем поиск раз в несколько месяцев.
- `tools/yandex_archive.js` — функции для консоли браузера на открытой вкладке Яндекс Архива: `__qd` (поиск со сниппетами), `__links` (ссылки на сканы), `__titles` (какие книги есть за год), `__scanBook` (перебор всех сканов книги по регулярке).

### «Память народа» и ОБД «Мемориал»
- Ищем и **без отчества**, и с годом ±2; имя — во всех формах.
- ОБД по месту рождения: `search.htm?f=P~<Фамилия>&pb=T~<Место>&...` — место целым словом.
- Номер команды в книге учёта призванных → тот же номер в именных списках других военкоматов того же месяца → часть.

### Живые генеалоги: ВГД и чаты Familio
Когда документы кончились, лучше всего работают люди, которые годами копают тот же район.
- **Форум ВГД** (forum.vgd.ru) — разделы по областям, уездам, фамилиям и архивам. Нужна регистрация. Сначала поиск по форуму: часто кто-то уже выложил выписки по вашему селу.
- **Telegram-чаты Familio** — региональные чаты генеалогов (`t.me/familio_<регион>`), плюс VK-группы по районам.
- Как писать пост: одна линия на пост; что известно (с метками 📄/👪), что ищем, какие фонды уже смотрели; без данных о живых.
- Ответы заносим в реестр с меткой 👪/🔎 и именем ответившего, проверяем по скану.

### Когда тупик
- Сплошной просмотр всех книг прихода за ±5 лет, восстановление **всех** семей села.
- Крёстные и поручители — круг родни; их фамилии — новые запросы.
- Соседние дела в описи: метрики иногда вшиты не туда.
- Письмо в архив или ЗАГС: просить **справку**, а не повторное свидетельство — в справке больше сведений.

## 3. Приватность

- **Живые — минимум данных.** Не ищем в сети адреса, телефоны, аккаунты живых. В веер и публичные посты — живых не вносим (кроме имени родителей в личной версии).
- **Сканы, фото, реестры с настоящими людьми — только в приватной папке**, не в git. В этом репо `.gitignore` уже закрывает `fanimg/`, картинки, `my/` и собранные HTML.
- Посты в чаты и на форумы — только про умерших предков.
- Перед публикацией чего угодно — grep по фамилиям семьи, телефонам, почтам.

## 4. «Веер предков»

Интерактивная страница-веер: в центре — вы, слева папина сторона, справа мамина, до 5–6 колена.
Клик по человеку — карточка: что известно, откуда (документ / со слов семьи / гипотеза), фото и сканы, ссылки на родителей.
Под веером — хроника рода с фильтром по линиям.
Один самодостаточный HTML-файл: картинки встроены, интернет не нужен, можно отправить родне в мессенджер.

### Собрать демо

```bash
cd fan
python3 fan_build.py demo/family.json demo.html
open demo.html
```

Нужен только Python 3, без библиотек.

### Своя семья

```bash
mkdir -p my/fanimg            # my/ закрыта в .gitignore
cp fan/demo/family.json my/family.json
# правим my/family.json, кладём фото и сканы в my/fanimg/
python3 fan/fan_build.py my/family.json my/Веер_предков.html
```

### Формат JSON

- `meta` — `title`, `subtitle`, `footer` (подписи на странице).
- `people` — словарь `путь → человек`. Путь — цепочка из `F` (отец) и `M` (мать) от центра:
  `""` — вы, `F` — папа, `FM` — мама папы, `MFF` — отец отца мамы и т. д.
  Поля: `n` имя-отчество, `s` фамилия, `y` годы, `p` место, `c` статус (`d` документ, `f` со слов семьи, `h` гипотеза — рисуется пунктиром),
  `t` список абзацев, `ph` фото и `dc` документы — списки `[файл, подпись]` из папки картинок.
- `lines` — линии рода: `k` ключ, `name`, `color`, `pre` — пути, с которых линия начинается (человек относится к линии по самому длинному совпавшему префиксу), `text`.
- `events` — хроника: `[год, ключ_линии или "ctx", статус (d/f/h/x), текст]`; `ctx` + `x` — события эпохи.

Пустые слоты родителей известных людей рисуются серым «?» — сразу видно, где следующий шаг поиска.

## 5. Как с этим работает ИИ-помощник

Мы ведём поиск вместе с Claude (Claude Code): он ходит по Яндекс Архиву, «Памяти народа», ОБД во встроенном браузере,
заносит каждый запрос в `search-log.csv`, находки — в реестры, держит `research-state.md` и пересобирает веер.
Капчи, вход в аккаунты и оплату госпошлин делает человек — ИИ копит их и отдаёт одной пачкой.
Реестры (`person / artifact / claims / relationship`) — формат с разделением «что написано в документе» и «что мы из этого вывели», чтобы любой вывод можно было проследить до скана.
